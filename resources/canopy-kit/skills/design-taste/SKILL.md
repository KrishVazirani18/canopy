# Default taste

Opinions, not rules. Use them only where the user and the project set nothing. A named style or an existing design always replaces them, and the user can turn this skill off.

## Overall bar

Finished like a well-funded product: Apple's product pages are the reference for polish. Polish is the floor, not the style. Every piece of work still needs a look of its own (canopy-kit:design, "Research before you build"); restraint below means no clutter, not no character. It should never look generated: too many cards, random colors, decoration with no purpose, or the default look of its category.

## Color

- A near-monochrome base (white or near-black) plus one accent.
- Color carries meaning: status, data, the one primary action. It does not decorate.
- Keep the accent flat and restrained. No glow, no gradients for their own sake, no extra hues.

## Type

- One deliberate pair: a display face with character, chosen for the work's style, and a plain text face. One family only when it has real character of its own. The system font is not a choice.
- Title Case for headings, buttons, nav and labels. No ALL CAPS.
- Moderate weights. Big type for the few things that matter, not bold everywhere.

## Shape and imagery

- Match corner radius to what's around it. Editorial pages suit sharp edges and thin rules.
- Real photos and real logos over illustrations and icons. Logos for named brands, paired with the name.
- Icons only where they help scanning: thin outline style, one meaning per icon. No decorative emojis.

## Copy

- Fewer words, more visuals. One clear line beats a paragraph.
- A second line only when it carries real information (a date, a price, what happens next).
- Plain and specific. It should read like a person wrote it.
